Getting started

The API is split into three groups:

  • Public — read published content and submit forms. No credentials needed. Used by the customer portal.
  • Auth — exchange admin email + password for a JWT.
  • Admin — full CRUD over every collection. Requires the JWT from the auth group.

Dates and timestamps on records use ts — a Unix epoch in milliseconds (a JS Number), not an ISO string. Mongoose also stamps createdAt / updatedAt on every document; public read endpoints strip those two fields, admin endpoints return them.

Response format

Every endpoint — success or failure, public or admin — returns the same envelope. Read the payload from data, and show the user message when something fails. Never branch on the body shape; branch on success or the HTTP status.

On success

{
  "success": true,
  "statusCode": 200,
  "message": "Companies fetched successfully",
  "data": …the payload: an object, an array, or null…
}

On failure

{
  "success": false,
  "statusCode": 400,
  "message": "Name and email are required.",
  "errors": [ …optional per-field details… ]
}

message is always safe to show an end user. errors carries { field, message } entries when a specific field caused the failure (validation, duplicate key, bad id) — use it to highlight the offending input. It is an empty array otherwise, never missing.

A minimal client: const { data, message } = await res.json(); if (!res.ok) throw new Error(message);

Authentication

Sign in once, then send the token on every admin request:

Authorization: Bearer <token>

Tokens are signed with JWT_SECRET and expire after JWT_EXPIRES_IN (default 7d). An expired, malformed or missing token returns 401 — "Sign in to continue." when the header is absent, "Your session expired. Sign in again." when the token itself is rejected.

CORS

Cross-origin requests to /api are rejected unless the calling origin is listed in the server's CORS_ORIGINS environment variable (comma-separated). If your frontend is served from the same host as this API, no configuration is needed.

Rate limits

  • POST /api/auth/login — 10 attempts per IP per 15 minutes.
  • All public form submissions (enquiries, callbacks, applications, questions, reviews, members) — 20 per IP per 10 minutes, counted across all six routes.
  • Admin routes are not rate limited.

Limits are reported in the standard RateLimit-* response headers. Exceeding one returns 429 in the usual failure envelope.
